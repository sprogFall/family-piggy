## 1. 一分钟速览

**一句话**：一个支持「个人账本 / 家庭账本」的记账 App，家人凭邀请码加入后可在同一个家庭账本里多人共同记账，流水经 Supabase Realtime 实时同步。

| 维度 | 事实 |
| --- | --- |
| 类型 | React Native（Expo 托管工作流）+ TypeScript strict 的移动 App |
| 后端 | Supabase：Auth + Postgres + RLS + Realtime + Storage |
| 代码规模 | 98 个源文件 / 约 9,727 行（不含测试）；另有 53 个测试文件 / 约 4,621 行 |
| 测试 | 53 个 suite、363 个用例，全部离线可跑，约 12 秒跑完（大头是图标资源门禁的解码校验） |
| 分层 | `screens → stores → services → lib`，`domain` 为纯函数底座 |
| 金额 | **一律以「分」（整数）存储与计算**，只在输入/展示层转「元」 |
| 状态 | zustand（9 个 store），无 Redux / 无 Context 业务状态 |
| 路由 | @react-navigation：底部 4 Tab + 中央记账按钮 + 12 个 Stack 页面 |
| 交付 | GitHub Actions 上 `expo prebuild + gradle assembleRelease` 出签名 APK，**不依赖 Expo / EAS 账号** |
| 更新 | App 内检查公开仓库的 GitHub Release → 下载（镜像回退 + 大小校验；默认跳过全量 SHA-256）→ 拉起系统安装器 |

## 2. 项目定位与功能

### 2.1 能力矩阵

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 邮箱注册 / 登录 | ✅ | 注册触发数据库触发器，自动建 `profiles` + 「个人账本」+ 默认分类 |
| 多账本切换 | ✅ | 个人账本 + 所属家庭的家庭账本，底部弹层切换；按账号持久化上次打开账本，重启 App 自动恢复 |
| 记一笔 / 编辑 / 删除 | ✅ | **顶部金额行整体加高（最小高度 96）**：左侧「币种 chip + 大号金额（`fontSize.display` 40pt，未输入时弱化色 0.00）」、右侧日期 chip，位于支出/收入之上，便于先确认币种、数额与时间；下方是支出/收入、分类九宫格、标签、备注、记账类型（是否报销）、账单图片（最多 3 张）；金额键盘保留加减乘除，金额下方、支出/收入选择上方为次级「再记一笔」与主色「完成」，提交前按标准优先级计算表达式；新建普通流水时「再记一笔」保存后以相同日期打开新的记账页 |
| 记账标签 | ✅ | 一笔流水可关联多个标签，`transactions.tag_names text[]` 保存标签名快照，删除标签库不影响历史账单；标签**隶属于分类**（`tags.category_id`）：选中分类后可多选历史标签或新增，未选分类时不展示也不能新增；账单列表按「餐饮[午餐,奶茶]」把标签拼在分类后展示 |
| 备注 / 记账类型 / 图片 | ✅ | `transactions.note` 为本笔独有备注，与可复用标签分开；`transactions.attributes` JSONB 预留记账类型扩展，当前用边框胶囊勾选「报销」，账单页可按全部 / 报销筛选；`transactions.images` 保存最多 3 个 Supabase Storage `transaction-images/<uid>/` 公开 URL，列表展示缩略图 |
| 定时记账 | ✅ | 「记一笔」记账类型中可选择「定时记账」，支持每月几号或每周周几；规则保存后不立即写入流水，由 Supabase Cron 每小时调用 `generate_due_recurring_transactions()` 到期生成真实流水；「我的 → 定时记账」可管理规则，支持编辑 / 删除 |
| 多币种 | ✅ | 每笔流水记录币种（CNY/USD/EUR/JPY/HKD/GBP，默认 CNY），明细按各自符号展示；汇总 / 占比 / 趋势 / 预算只统计当月主币种（出现次数最多者），另有外币时提示「另有 N 笔外币记录未计入」，绝不跨币种相加 |
| 字体大小 | ✅ | 「设置 → 字体大小」四档：小 / 标准 / 大 / 超大（标准 = 设计基准），本地持久化；预览样例卡即时变化，切换后整个应用立即生效（无需重启） |
| 深色模式 | ✅ | 「设置 → 深色模式」三档：跟随系统 / 浅色 / 深色，本地持久化；浅色与深色两套调色板（深色为微信风格：页面底 `#111111`、卡片 `#1E1E1E`、正文 `#EDEDED`），跟随系统档随手机深浅色实时切换，切换后整个应用立即生效（无需重启） |
| 应用内更新 | ✅ | 「关于我们」页用应用图标 + 更新卡片展示；检查 GitHub Release（仅正式版）→ 应用内下载（镜像回退）→ 默认只校验资产大小，仅当 Release 说明显式提供 SHA256 时才做 4MB 分块哈希并展示校验进度；APK 完整性由 Android 安装器签名校验兜底 → 拉起系统安装器；可忽略指定版本 |
| 账单列表 | ✅ | 按天分组、日小计、月汇总条；支持按收入 / 支出、记录人筛选，支持按分类 / 标签关键词搜索；点击行进入账单预览（预览页可修改 / 删除），左滑行露出编辑 / 删除 |
| 月度预算 | ✅ | 按账本存 `ledgers.monthly_budget`（分），首页汇总卡显示进度与超支 |
| 统计 | ✅ | 支持本月 / 本周 / 本年 / 最近 30 天等快捷周期与按周 / 月 / 年 / 自定义日期区间查询，默认本月；家庭账本可按成员筛选；趋势卡支持支出 / 收入 / 结余 / 收支与柱状 / 曲线切换，带横纵坐标并支持触摸查看金额；分布卡支持支出 / 收入 / 收支三种口径，展示各分类金额、占比与笔数，点击分类可下钻当前周期 / 成员条件下的明细；底部保留支出 / 收入金额倒序排行，默认前 10 条，滚动分页加载更多，可点击进入账单预览并展示标签 |

## 4. 五分钟上手

### 4.1 配置 Supabase（一次性）

1. 在 [supabase.com](https://supabase.com) 建项目；
2. Dashboard → SQL Editor，**整体执行** `supabase/schema.sql`。该脚本是幂等的，可重复执行；
   - 旧库再按文件名顺序执行 `supabase/migrations/` 下的增量脚本：
     1. `20260928080631_tags_and_ledger_select_fix.sql`：曾用 `transactions.note` 存备注的库，历史备注逐条升级为标签，并修复 `ledgers` 的 SELECT 策略；
     2. `20260928220000_tag_category_and_tx_currency.sql`：`tags` 由「账本 + 收支类型」改为「账本 + 分类」归属（`category_id`，历史标签按其被使用的流水回填分类，未被引用的历史标签删除），`transactions` 增加 `currency`（默认 `CNY`）；
     3. `20260929090000_transaction_note_types_images.sql`：重新引入独立的 `transactions.note`（与标签分开、不可复用），增加 JSONB `attributes`（预留在前、当前支持是否报销）和 `images`（最多 3 张，CHECK 约束），并创建 `transaction-images` Storage 桶与策略；
     4. `20260930090000_import_recorder_mapping.sql`：`transactions` 的 INSERT 策略放宽为家庭账本可按同家庭成员映射导入记录人；
     5. `20260930100000_transaction_multi_tags.sql`：`transactions` 用 `tag_ids uuid[]` 取代单值 `tag_id` 并把历史标签回填进数组，新增标签归属校验 / 删除清理触发器；
     6. `20260930110000_family_management.sql`：新增家庭改名（同步家庭账本名）与重新生成邀请码 RPC；
     7. `20260930120000_transaction_tag_names.sql`：流水的 `tag_ids` 关联改为 `tag_names text[]` 快照，历史标签回填，删除标签不再影响存量流水；
     8. `20261001090000_recurring_rules.sql`：新增 `recurring_rules` 定时记账规则表、流水 `recurring_rule_id` 与防重唯一约束，新增到期生成函数并尝试创建每小时 Cron 调度；
3. 复制 `.env.example` 为 `.env`：

```bash
EXPO_PUBLIC_SUPABASE_URL=https://<your-project>.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=<your-anon-key>
```

> 仓库中**不允许**出现任何真实连接信息。`.env` 已被 `.gitignore` 忽略，只有 `.env.example` 入库。

`schema.sql` 一次执行会建好：8 张表、索引、17 个函数、4 个触发器、全部 RLS 策略、Realtime 发布、`avatars` 存储桶与策略，以及**注册自动建档 / 新账本自动播种 17 个默认分类**。启用 `pg_cron` 后，自动定时记账还会创建每小时调度任务。

> 如果 SQL 执行时提示 `pg_cron` 不可用，请在 Supabase Dashboard → Database → Extensions 启用 `pg_cron`，然后手动执行：
>
> ```sql
> select cron.schedule(
>   'generate-recurring-transactions',
>   '0 * * * *',
>   $$select public.generate_due_recurring_transactions();$$
> );
> ```

## 6. 架构总览

### 6.1 分层与依赖方向（**不可违反**）

```
screens ──► stores ──► services ──► lib/supabase
   │           │           │
   └───────────┴───────────┴──► domain（纯函数，可被所有层复用）
                                types / theme（无依赖的类型与令牌）
```

| 层 | 职责 | 硬性约束 |
| --- | --- | --- |
| `domain/` | 金额、日期、统计、图表几何、CSV 解析、校验 | **零外部业务依赖**，纯函数，必须 100% 可测 |
| `services/` | Supabase 数据访问，行类型 ↔ 领域类型映射 | 唯一允许直接 `import { supabase }` 的地方（除 `lib`） |
| `stores/` | zustand 全局状态，编排 services | 不含 SQL，不写 UI 文案以外的业务规则 |
| `screens/` | 页面与交互编排 | **禁止直连 Supabase**，禁止内联业务计算（调 domain） |
| `components/` | 可复用 UI | 无数据获取，纯 props 驱动 |
| `navigation/` | 路由定义与参数类型 | 页面注册的唯一入口 |
| `theme/` | 浅色 / 深色两套调色板、间距、字号、图标映射与样式工厂 | 禁止在组件里硬编码色值，颜色只能经 `makeStyles` / `useColors` 获取 |
| `types/` | 领域类型 + DB 行类型映射 | `db.ts` 的 `toXxx()` 是唯一的字段改名点 |
| `lib/` | supabase client、跨平台弹窗、错误文案 | |

### 6.2 目录结构

```
src/
  domain/      14 个纯函数模块 + 测试
  services/     11 个数据访问模块 + 测试
  stores/       9 个 zustand store + 测试
  components/   8 个业务组件 + ui/（16 个基础组件）+ charts/（2 个图表 + 1 个悬浮浮层）
  screens/      13 个功能目录、17 个页面
  navigation/   index.tsx（路由注册）+ types.ts（参数类型）
  theme/        index.ts（令牌 + makeStyles/useColors 样式工厂）+ palette.ts（浅色/深色两套调色板）
                + scheme.ts（深色模式解析）+ font-scale.ts（四档字号）+ icons.ts（分类图标映射）
  types/        domain.ts（领域模型）+ db.ts（Supabase 行类型与映射）+ github.ts（GitHub Release 行类型与映射）
  lib/          supabase.ts / alert.ts / errors.ts
  hooks/        useActiveLedgerData.ts（跨 store 派生 hooks：活性账本 / 分类 / 标签 / 月份流水 / 家庭成员与记录人标注）
  test/         supabase-mock.ts（查询链测试替身）
assets/         icon.png（通用图标）+ adaptive-icon.png（Android 自适应前景），均 1024×1024
supabase/       schema.sql（幂等初始化脚本）+ migrations/（增量迁移脚本）
```

### 6.3 启动与登录态编排

`App.tsx` 是唯一的根编排点：

- 挂载时 `useAuthStore.initialize()`（先注册会话监听，再读会话）、`useSettingsStore.hydrate()`（读取本地字号档位）与 `useThemeStore.hydrate()`（读取本地深色模式档位），并注册 `Appearance.addChangeListener` 把系统深浅色同步进 `theme.store`；
- `status === 'loading'` → 渲染 `components/SplashView`（应用图标 `AppLogo` + ActivityIndicator）；
- `status === 'signedIn'` → `MainNavigator` 并触发 `useLedgerStore.load()`；
- `status === 'signedOut'` → `AuthNavigator`，并 `reset()` 掉 ledger / transaction / category / tag 四个 store（防止串号残留数据；字号与深色模式属于设备级设置，不清除）；
- `NavigationContainer` 的 `theme` 与 `StatusBar` 的 `style` 都按当前配色取值，避免切页时闪出浅色底；
- 全局 `<Toast />` 挂在 `NavigationContainer` 之外，任何页面调 `useToastStore.show()` 都能弹出。

## 7. 四条核心数据流

### 7.1 记账写入链路

```
AddTransactionScreen
  ├─ 标签：选中分类后输入新标签 → tagStore.ensure() ──► tagService.ensureMany(ledgerId, categoryId, names)（upsert，同分类下同名复用）
  ├─ 备注 / 记账类型：note + attributes{reimbursement} 随流水入库，与标签分开
  ├─ 图片：transactionImageService.upload() ──► transaction-images/<uid>/... 公开 URL（最多 3 张）
  └─ evaluateAmountExpression(表达式) ──► parseAmountToCents(「元」字符串) ──► 分（int）
       └─ useTransactionStore.add(input{tagIds,note,attributes,images})
            ├─ useAuthStore.session.user.id ──► createdBy
            ├─ transactionService.create()  ──► Supabase insert + select
            └─ patchLedgerBuckets()          ──► 本地桶即时更新（无需等待 realtime）
                 └─ showToast('记账成功') + navigation.goBack()
```

本端写完立刻改本地桶，**不依赖 realtime 回环**；realtime 只负责把**别人**的写入补进来。

### 7.2 家庭账本实时协作

```
HomeScreen / BillsScreen 的 useFocusEffect
  ├─ loadMonth(ledgerId, month)     拉当月流水到 buckets[`${ledgerId}::${yyyy-MM}`]
  ├─ loadCategories(ledgerId)       拉分类
  └─ subscribe(ledgerId)            ──► supabase.channel(`transactions-<ledgerId>-<seq>`)
                                          filter: ledger_id=eq.<ledgerId>
        INSERT/UPDATE ──► upsertLocal()（仅落入时间匹配的月份桶）
        DELETE        ──► deleteLocal()
  （离开页面时返回的取消函数执行 supabase.removeChannel）
```

> topic 里的递增序号是**必须保留**的修复：固定 topic 会命中上一个「尚未异步移除完成」的 channel，`channel.on()` 会同步抛 `cannot add callbacks after subscribe()`，在 `useFocusEffect` 里直接导致闪退。

### 7.3 成员记账标注链路

```
BillsScreen
  └─ useCreatorLabel()                       （hooks/useActiveLedgerData）
       ├─ ledger.type !== 'family' ──► 恒返回 null（个人账本不标注）
       ├─ useActiveFamilyMembers()          家庭账本自动确保成员已加载
       │    └─ ledgerStore.loadMembers(familyId) ──► familyService.listMembers
       │         └─ family_members + profiles（RLS：shares_family 允许同家庭互读昵称）
       └─ creatorLabel(createdBy, members[createdBy].nickname)
            └─ 有昵称 → 昵称（本人也显示昵称，不再显示「我」）；资料缺失 → null（UI 自动隐藏）
  └─ DaySection(creatorNameOf) ──► TransactionRow(createdByName)
       主标题 = 「餐饮[午餐,奶茶]」；副标题 = 「14:30 · 张三」
```

> 成员加载失败（离线 / 权限异常）时静默降级为不标注，**不影响记账主流程**。

### 7.4 月份桶（bucket）缓存模型

`transaction.store` 用 `Record<`${ledgerId}::${yyyy-MM}`, { status, transactions }>` 做缓存：

- 首页 / 账单 / 统计 / 导出各自的 `useFocusEffect` 负责「按需加载当月」；
- 切月只加载目标月份，已加载的月份保留在内存；
- 编辑跨月流水（改了 `occurredAt`）后，store 会**重拉该账本所有已加载月份桶**，保证归属月份正确；
- selector 在「未加载 / 无账本」时必须返回**模块级常量空数组**，否则 zustand v5 的 `useSyncExternalStore` 会因快照引用每次都变而无限重渲染。

## 8. domain 领域层

纯函数，无副作用，全部有测试覆盖。

### 8.1 `money.ts` — 金额

| 函数 | 说明 |
| --- | --- |
| `parseAmountToCents(input)` | 「元」字符串 → 分。接受千分位逗号与首尾空格；**拒绝**空串、负数、三位小数、>9 位整数；`<= 0` 返回 `null` |
| `formatCents(cents, opts?)` | 分 → 元字符串。默认千分位 2 位小数；`signed` 给正数加 `+`；`thousands: false` 关闭千分位 |
| `formatRatio(ratio)` | `0~1` → 整数百分比文本 |

### 8.2 `amount-input.ts` — 金额键盘规则

| 导出 | 说明 |
| --- | --- |
| `AMOUNT_KEYS` | 数字/小数点/退格 + 加减乘除按键 |
| `pressAmountKey(current, key)` | 返回按键后的新表达式；连续运算符会被归一化，非法按键返回原值 |
| `evaluateAmountExpression(expression)` | 表达式按标准优先级求值，结果固定两位小数；空表达式、连续运算符、除零、超范围返回 `null` |
| `formatEvaluatedAmount(value)` | 结果展示时去掉尾随 `0`（`49.00 -> 49`、`12.50 -> 12.5`），用于顶部大号实时结果 |
| `MAX_INTEGER_DIGITS = 9` / `MAX_DECIMAL_DIGITS = 2` | 单个操作数位数上限 |

规则：首个 `0` 被数字替换（不出现 `05`）；重复小数点忽略；空串按 `.` 补成 `0.`；输入表达式时 `AmountPanel` 主文案实时显示 `evaluateAmountExpression` 结果、灰色小字保留表达式（如主文案 `49`、副文案 `50-1`）；完成时再按同一规则计算 `12+5×2`。

### 8.3 `dates.ts` — 日期

全部基于**本地时区**。

`makeMonth` / `addMonths`（跨年正确）/ `monthKey`（`2024-05`）/ `monthLabel`（`2024年5月`）/ `currentMonth` / `daysInMonth`（闰年正确）/ `monthRangeISO`（`[start, end)`，直接喂给 DB 范围查询）/ `recentMonths` / `dayKeyOf` / `dayLabelOf`（`5月20日 星期二`）/ `dateLabelOf` / `timeLabelOf` / `parseDateTimeCN`（解析 `yyyy-MM-dd HH:mm`）。

### 8.4 `statement.ts` — 统计

| 函数 | 说明 |
| --- | --- |
| `monthSummary(txs)` | `{ expense, income, balance }`（分） |
| `groupByDay(txs)` | 按天分组，**最新日期在前**，组内带 `expense` / `income` 小计 |
| `breakdown(txs, kind, nameOf)` | 指定类型的分类汇总，金额降序，带 `ratio` |
| `breakdownWithOther(txs, kind, nameOf, topN=5)` | Top N 之外合并为「其他」 |
| `trendByDay(txs, month)` | 整月逐日收支，缺失天补 0 |

### 8.5 其余模块

| 文件 | 内容 |
| --- | --- |

### 10.1 四个必须遵守的 store 约定

1. **selector 返回稳定引用**：`selectCategories` / `selectMembers` / `selectMonthTransactions` 在空态返回模块级常量数组。破坏这条 → 无限重渲染。
2. **`useActiveLedgerData.ts` 是跨 store 组合的唯一入口**：`useActiveLedger` / `useActiveCategories` / `useCategoryOf` / `useMonthTransactions`。页面不要自己拼多个 store。
3. **写操作先落库再改本地**：所有 action 都是 `await service.xxx()` 后再 `set()`；失败则抛出，由页面 `showAlert`。
4. **登出必须 `reset()`**：`App.tsx` 已统一处理，新增全局 store 时记得补上。

### 11.3 页面编写的既有模式

- 进页面拉数据统一用 `useFocusEffect(useCallback(..., [ledger?.id, monthKey]))`，返回取消订阅函数；
- 依赖数组刻意用 `ledger?.id` 与 `monthKey` 字符串，避免对象引用变化导致重复订阅（伴随 `eslint-disable-next-line react-hooks/exhaustive-deps` 注释）；
- 所有反馈走 `showAlert`（跨平台）或 `showToast`（轻提示），不用裸 `Alert.alert`；
- 危险操作一律二次确认（`style: 'cancel'` + `style: 'destructive'`）。

## 13. theme 设计令牌

`theme/palette.ts`：`LIGHT_COLORS` / `DARK_COLORS` 两套令牌，由 `ThemeColors` 接口约束键必须一一对应（`scheme.test.ts` 额外校验）：

- 通用令牌：`primary #00B578`、`primaryDark`、`primaryLight`（选中态 / 图标底板）、`primaryDisabled`、`bg`、`card`、`border`、`text`/`textSecondary`/`textTertiary`、`income`、`expense`、`danger #FA5151`、`white`（**彩色底上的文字与图标**，深浅两套都保持纯白）、`toastBg`、`ripple`、`scrim`（弹层遮罩）、`infoLight`（信息类浅底）；
- 浅色：`bg #F7F8FA` / `card #FFFFFF` / `text #1A1A1A`；
- 深色（微信风格）：`bg #111111` / `card #1E1E1E` / `border #2C2C2C` / `text #EDEDED`，品牌绿与 `white` 与浅色保持一致。

`theme/scheme.ts`（纯函数，不持有状态）：

- `THEME_MODES = ['system','light','dark']`、`THEME_MODE_LABELS`、`DEFAULT_THEME_MODE = 'system'`；
- `resolveScheme(mode, systemScheme)`：跟随系统时取系统配色，手动档位覆盖系统；`toColorScheme()` 把未知 / 空值归一成浅色；
- `paletteOf(scheme)`：按配色取令牌。

`theme/index.ts`：

- `makeStyles((colors) => ({...}))`：返回 `useStyles()` 钩子，组件内在函数体**最前面无条件**调用 `const styles = useStyles()`；渲染时按「当前配色 + 当前字号档位」执行工厂并物化 `fontSize` / `lineHeight`，同一组合只物化一次并缓存（组合不变返回同一引用、组合变化必换引用，RN Fabric 的 `diffProperties` 才会把新样式下发原生）；
- `useColors()`：取当前调色板，用于样式对象之外的场景（`Ionicons color=`、`placeholderTextColor`、SVG 的 `stroke`/`fill`、内联 `{ backgroundColor: colors.x }` 等）；
- `useFontScale()` / `scaleFontSize(base, key)`：不在样式工厂里的字号（如 Tab 文案）需显式按档位缩放；`scaleFontSize` 是**纯函数**，档位必须显式传入；
- `CHART_PALETTE`：9 色图表调色板（环形图与图例共用，靠 index 对齐）；
- `radius`：`sm 6 / md 10 / lg 14 / round 999`；
- `fontSize`：`xs 11 / sm 13 / md 15 / lg 17 / xl 20 / xxl 26 / display 40`（基准值，运行期按字号档位缩放）；
- `space(n) = n * 4`（4pt 栅格）；
- `TABBAR_HEIGHT = 58`（Toast 定位也用它）、`AMOUNT_ROW_MIN_HEIGHT = 96`（「记一笔」金额行最小高度）。

`theme/font-scale.ts`：`FONT_SCALE_KEYS` / `FONT_SCALE_LABELS` / `DEFAULT_FONT_SCALE` / `isFontScaleKey` / `scaleFontSize`，纯函数，档位本身存在 `settings.store`。

`theme/icons.ts`：

- `CATEGORY_VISUALS`：19 个图标 key → `{ icon: Ionicons 名, color }`；
- `ICON_CHOICES`：分类编辑弹窗的可选列表（与上表 key 一一对应）；
- `categoryVisual(key, fallbackColor)`：未命中时回退 `ellipse`。

> 新增分类图标必须**同时**改 `CATEGORY_VISUALS` 与 `ICON_CHOICES`，否则图标选了不显示。

### 14.3 RLS 策略矩阵

| 表 | select | insert | update | delete |
| --- | --- | --- | --- | --- |
| `profiles` | 本人 或 同家庭成员 | — | 仅本人 | — |
| `families` | 自己的 或 所在家庭 | `owner_id = auth.uid()` | 仅 owner | 仅 owner |
| `family_members` | 本人 或 同家庭 | `user_id = auth.uid()` | — | 本人 或 家庭 owner |
| `ledgers` | `can_access_ledger(id)` | `owner_id = auth.uid()` | 仅 owner | 仅 owner |
| `categories` | `can_access_ledger(ledger_id)` | 同左 | 同左 | 同左 |
| `tags` | `can_access_ledger(ledger_id)` | 同左 | 同左 | 同左 |
| `transactions` | `can_access_ledger(ledger_id)` | `can_access_ledger(ledger_id)` + `can_record_as_user(ledger_id, created_by)` | `created_by` 或 账本 owner | 同 update |
| `recurring_rules` | `can_access_ledger(ledger_id)` | `can_access_ledger(ledger_id)` + `created_by = auth.uid()` | `created_by` 或账本 owner | 同 update |

> **写策略时的铁律**：策略内禁止直接或间接查询本表 / 互相引用的表，跨表判断一律走 `security definer` 辅助函数，否则触发无限递归。

> **`INSERT ... RETURNING` 与 stable 函数的坑**：supabase-js 的 `.insert().select()` 会用 SELECT 策略过滤返回行，而 `can_access_ledger` 是 **stable** `security definer` 函数，在同一条 INSERT 语句内看不到刚插入的行。因此涉及**本行主键**判断的表（`ledgers`）必须把策略写成 `owner_id = auth.uid() or can_access_ledger(id)`，或像 `ledger.service` / `family.service` 那样写入后**另起语句回读**；`tags` / `categories` / `transactions` 的策略判断的是**已存在的 `ledger_id`**，不受影响。

## 16. 构建与发布（CI/CD）

三条工作流全部固定在 `ubuntu-24.04`（避免 `ubuntu-latest` 迁移导致构建环境被动突变）。

| 工作流 | 触发 | 内容 |
| --- | --- | --- |
| `ci.yml` | push / PR → `main` | `npm ci` → `npm run typecheck` → `npm test -- --ci` |
| `warm-android-cache.yml` | push 改动 `package.json`/`package-lock.json`/`app.config.js`/自身，或手动 | 在 main 作用域预热 Gradle 缓存（缓存按 ref 隔离，tag 构建只能读默认分支缓存） |
| `release.yml` | 推 `v*` 标签 或 手动 | `expo prebuild` → Gradle `assembleRelease` → 签名 → `apksigner verify` → **发布 Release 资产（可直接下载的 .apk）** |

### 16.1 发布流程要点

- **不依赖 Expo / EAS 账号**：Runner 上 JDK 17 + Android SDK 由镜像自带；
- 步骤：校验 5 个 Secrets 是否齐全 → 解析版本与发布标签 → 还原 keystore → `prebuild` → 把 Gradle 分发包从 `-all.zip` 换成 `-bin.zip`（省约 100MB 冷启动下载）→ `assembleRelease` 注入签名参数 → 校验签名不是 `CN=Android Debug` → 生成 `.apk.sha256` 附件 → `gh release create/upload` 同时发布 `family-piggy-<tag>.apk` 与 `family-piggy-<tag>.apk.sha256`；
- Release 说明默认不再写入机器可读的 `SHA256:` 行；App 因此只做资产大小校验，`.apk.sha256` 附件供手动核验。若某次需要恢复 App 内分块哈希，只需在说明中显式加入 `SHA256: <64 位十六进制>`。同一标签重跑时用 `gh release edit --notes` 一并刷新，保持幂等；
- **产物为什么不是 Actions Artifacts**：Artifacts 会被 GitHub 强制打包成 zip，下载后还要解压；Release 资产才是可直接点击下载安装的 `.apk`；
- 发布标签规则：推标签 → 用该标签发正式 Release；手动触发 → `build-<run_number>` 预发布（`--target` 指向当次构建的 SHA）。同一标签重跑走 `gh release upload --clobber`，保持幂等；
- 需要 `permissions: contents: write`（工作流已声明）；仓库若把默认 `GITHUB_TOKEN` 设为只读，需在 Settings → Actions → General 放开；
- **刻意不在 release 里重复跑 typecheck + jest**：tag 指向 main 上的提交，push 到 main 时 `ci.yml` 已对同一 SHA 跑过。⚠️ 因此**不要从未经 CI 的提交直接打标签**（Metro / Gradle 不做类型检查）。

### 16.2 版本注入链路

```
github.run_number → ANDROID_VERSION_CODE → app.config.js 的 android.versionCode（每次构建递增，保证可覆盖升级）
tag v0.1.2        → APP_VERSION          → app.config.js 的 version（去掉前缀 v）
```

### 16.3 Secrets（Settings → Secrets and variables → Actions）

| Secret | 用途 |
| --- | --- |
| `SUPABASE_URL` | 注入 `EXPO_PUBLIC_SUPABASE_URL` |
| `SUPABASE_ANON_KEY` | 注入 `EXPO_PUBLIC_SUPABASE_ANON_KEY` |
| `ANDROID_KEYSTORE_BASE64` | keystore 的 Base64 单行文本 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 密码（PKCS12 下 key 密码相同） |
| `ANDROID_KEY_ALIAS` | keystore 别名 |

> `EXPO_PUBLIC_*` 会被内联进 bundle，属公开信息；真正要保密的是 keystore 与其密码。keystore 生成后**务必备份**，丢失后无法覆盖升级已安装的 App。

### 16.4 构建失败速查

| 现象 | 处理 |
| --- | --- |
| `Plugin [id: 'expo-module-gradle-plugin'] was not found` | node_modules 混入了别的 SDK 版本原生模块；`npx expo install --check` 看清单，再用 `npx expo install <包名>` 装回 |
| `Could not get unknown property 'release' for SoftwareComponent container` | 同上，版本错配的连带报错 |

## 17. 编码规范速查

摘自 [`AGENTS.md`](../AGENTS.md)，此处只列**日常最常踩的**：

1. **TDD 强制**：红 → 绿 → 蓝。`domain` / `services` / `stores` 的所有逻辑必须有对应测试。提交前 `npm test` + `npm run typecheck` 必须全绿。
2. **彻底改造**：需求变更就整体重构相关模块，禁止打补丁、禁止保留旧实现兼容、禁止注释掉的死代码。改完即删旧代码/旧类型/旧测试。
3. **金额一律用「分」**（整数）存储与计算，只在输入/展示层转「元」。
4. **禁止 `any`**（确有逃逸必须注释原因）；仅函数组件 + Hooks，禁止 class 组件。
5. **页面禁止直连 Supabase**，必须经 `services`。
6. **UI 值统一走 `src/theme`**，禁止散落硬编码颜色/间距/字号。
7. **单文件 ≤ 300 行**，超出必须拆分；命名自释；魔法值收敛到常量。
8. **提交信息**用 `feat / fix / refactor / test / docs / chore` 前缀，一次提交一个完整意图。
9. **禁止提交真实密钥 / 连接信息**；新增环境变量必须同步更新 `.env.example` 与 README 的 Secrets 表。
10. **新表必须启用 RLS 并写策略**；需要实时同步的表要加入 `supabase_realtime` publication。

## 19. 常见变更操作手册

### 19.1 新增一个纯业务规则

1. 在 `src/domain/<模块>.ts` 写好函数签名（保持纯函数、无 import 业务层）；
2. **先**写 `src/domain/<模块>.test.ts` 的失败用例（边界值必写）；
3. 实现到测试通过；魔法值收敛成命名常量。

### 19.2 新增一个数据访问方法

1. 加在对应 `src/services/<域>.service.ts`；
2. 返回值必须是**领域类型**，行转换走 `types/db.ts` 的 `toXxx()`（新增字段就在这里映射）；
3. 错误统一 `throw new Error('<中文文案>')`；
4. 用 `createQueryChain` / `queryError` 写测试，断言字段映射（snake_case 与 bigint 归一）与错误文案。

### 19.3 新增一个页面

1. 建 `src/screens/<功能>/XxxScreen.tsx`（函数组件，数据走 stores / hooks）；
2. 在 `src/navigation/types.ts` 的 `RootStackParamList` 加路由与参数类型；
3. 在 `src/navigation/index.tsx` 的 `MainNavigator` 注册 `<RootStack.Screen>`；
4. 从入口页 `navigation.navigate('Xxx')`；
5. 顶部用 `AppHeader`（Stack 页）或 `ScreenTopBar`（Tab 页）保证状态栏安全区。

### 19.4 新增一张数据表

1. 在 `supabase/schema.sql` 追加**幂等**建表语句（`create table if not exists` + 行内注释 + `COMMENT ON`）；
2. `alter table ... enable row level security` + `drop policy if exists` / `create policy` 成对书写；
3. 跨表判断一律用 `security definer` 辅助函数，绝不在策略里直接查本表；
4. 索引按查询路径补（`create index if not exists`）；
5. 需要实时同步则加进 `supabase_realtime` publication（参照现有 `do $$` 块）；
6. 在 `src/types/db.ts` 补 `XxxRow` 与 `toXxx()`，在 `src/types/domain.ts` 补领域类型；
7. **线上已有数据库**时，另在 `supabase/migrations/<日期时间>_<用途>.sql` 写一份**只做增量**的脚本（改列 / 迁数据 / 改策略），并在 README 的配置步骤里注明；`schema.sql` 是「新库一次性初始化」，老库靠迁移脚本追平。

### 19.5 新增一个环境变量

1. `src/lib/supabase.ts` 或 `app.config.js` 读取 `process.env.EXPO_PUBLIC_*`；
2. 更新 `.env.example`；
3. 更新 README 的 Secrets 表；
4. 在 `release.yml` 的 job env / 校验步骤中注入并断言非空。

### 19.6 新增一个分类图标

`src/theme/icons.ts` 里**同时**补 `CATEGORY_VISUALS`（icon + color）与 `ICON_CHOICES`。

### 19.7 调整字号 / 深色模式 / 新增页面样式

1. 页面样式一律用 `const useStyles = makeStyles((colors) => ({...}))`（不是 `StyleSheet.create`），组件内 `const styles = useStyles()`，且必须放在函数体最前面（早于任何提前 return，遵守 hooks 规则）——`fontSize` / `lineHeight` 会按当前档位自动缩放，颜色随深浅色切换；
2. 样式对象之外的取色（图标 `color=`、`placeholderTextColor`、SVG、内联样式）用 `const colors = useColors()`；**禁止**在模块作用域读颜色，也禁止硬编码中性色（遮罩用 `colors.scrim`、信息浅底用 `colors.infoLight`）；
3. `fontSize.xxl` / `fontSize.display` 等令牌写的是**标准档基准值**，不要手写乘好比例的数值；
4. 新增屏幕直接注册进 `navigation/index.tsx` 即可：样式工厂自身订阅了配色与档位，屏幕不需要额外包一层高阶组件；
5. 新字号档位只需改 `theme/font-scale.ts` 的 `FONT_SCALE_KEYS` / `FONT_SCALE_LABELS` / 比例表；
6. 新增颜色令牌必须**同时**补 `theme/palette.ts` 的 `LIGHT_COLORS` 与 `DARK_COLORS`（`scheme.test.ts` 会校验两套键一致）；新增深色模式档位改 `theme/scheme.ts` 的 `THEME_MODES` / `THEME_MODE_LABELS`。

git checkout main && git pull
# 2) 打 annotated tag，说明写面向用户的简洁更新点（规范见 AGENTS.md 7.1）
git tag -a v0.1.3 -m "v0.1.3：本次更新主题" -m "- 用户可感知更新点 1
- 用户可感知更新点 2"

### 19.9 更换应用图标

`app.config.js` 引用两个 1024×1024 PNG：`assets/icon.png`（`expo.icon`，iOS / 旧版 Android 通用）与 `assets/adaptive-icon.png`（`android.adaptiveIcon.foregroundImage`，Android 8+ 自适应）。换图只覆盖这两个文件即可，无需改代码；`app.config.test.js` 会拦住不合规的图。

> 界面里的图标同样是这一份资源，统一由 `components/ui/AppLogo` 渲染（内部 `import appIcon from '../../../assets/icon.png'`，`*.png` 的类型声明见 `src/types/assets.d.ts`）：开屏（`components/SplashView`）、登录页、关于我们页三处都用它，换图后同步更新，不需要改代码。**不要再各自画「绿底 ¥」这类占位**——历史上前两者就是占位，与启动器图标不一致。JS 起来之前的**原生开屏**同样用这张 `icon.png`（见 19.11）。

设计稿通常是「带白边 / 带圆角的白底方块」，**必须先把白边处理掉**，否则：

- 通用图标四角会留白，iOS 圆角遮罩内会出现白角；
- 自适应图标被圆形遮罩裁到圆角外的白底，四角发白；
- 主体贴边时会被遮罩裁掉（笔记本 / 铅笔 / 叶子会被切）。

处理步骤（本仓库当前图标即由此流程生成）：

1. **定位方块**：找严格绿色背景像素的包围盒，取正方形边长，得到 `(X0, Y0, side)`；用顶边若干行的首个绿色像素偏移拟合圆角半径 `R`（当前 `R ≈ 0.262 × side`）。
2. **满幅无缝**：输出画布取 1024×1024，把方块按比例居中放进去；**方块外的像素不要填单一色**，而是「从中心沿射线走到圆角边界再往内 5px 采样」——这样四周与四角的填充色与边界完全连续，圆角边界不可见。注意圆角边缘有 1~2px 抗锯齿（偏白），直接把边界当采样起点会留下一圈细缝，所以采样要往内缩。
3. **放大到主体为主**：方块占画布越小，里面的账本越显得小。设方块缩放为 `s`，则方块占画布 `801 × s / 1024`，任意「以方块边长计」的半径 `r` 换算到画布为 `r × s × 0.782`。先量出主体的最大半径：用「与左右 12px 线性插值的偏离」当边缘强度，在圆角方块内部（排除四角白底）取强度 > 120 的像素，得到**实体轮廓最大半径 ≈ 0.467 × side**；再放宽到强度 > 35 会量到**叶子外侧尖端 ≈ 0.59 × side**，它才是真正的瓶颈（设计稿里叶子几乎贴到方块左边缘）。
4. **两档缩放**：圆形遮罩半径是画布宽的 1/2，所以自适应图标要求 `r × s × 0.782 ≤ 0.5`——按叶子尖端算 `s ≤ 1.08`，当前取 **1.05**（叶子完整、留 3% 余量，账本约占画布 2/3 宽）；通用图标不受圆形遮罩约束（iOS / 华为等只切四角），当前取 **1.15**（账本约占画布 72%）。
5. **自检**：`npx jest app.config.test.js` 会校验「文件存在 / 1024×1024 / 最外圈无白边 / 主体在安全区」；另外可用圆形、圆角方形遮罩各合成一张预览图肉眼确认主体没有被裁。
6. **别把背景当主体**：用「颜色偏暗 / 偏暖」这类简单判据很容易把背景误判成主体——背景右下角最暗处 min 通道只有 95，叶子也是绿色系，都骗得过朴素阈值，会算出虚高的半径并导致主体被压小。判据必须基于「相对局部平滑背景的偏离」或已知类别色。

> 圆角半径、缩放比例这类数值只影响生成过程，不进仓库；仓库里只保留两张成品 PNG 与门禁测试。

### 19.10 应用内更新（GitHub Releases 通道）

**目的**：用户不必自己上 Releases 页面下载 APK，App 内即可完成「检查 → 下载 → 校验 → 安装」。

```
AboutScreen（components/UpdateCard.tsx）
  → stores/update.store.ts（状态机 + 「已忽略版本」持久化）
    → services/update.service.ts
      → GET https://api.github.com/repos/sprogFall/family-piggy/releases/latest
      → expo-file-system 下载（镜像回退 + 进度回调）
      → 资产大小校验（默认跳过 SHA256；仅说明显式提供时才走 domain/sha256.ts 分块哈希）
      → expo-intent-launcher 拉起系统安装器
```

**前置条件**：仓库必须为**公开**。私有仓库匿名访问 API 与 Release 资产都返回 404，此时状态为 `unavailable`，卡片显示「暂时无法获取更新信息」而非报错。

| 项 | 约定 |
| --- | --- |
| 更新说明 | tag 发布时使用 annotated tag 的说明作为 Release 正文，App 更新卡片直接展示；workflow 默认不再追加 `SHA256:` 行，改发布 `.apk.sha256` 附件供手动核验 |
| 只认正式版 | `/releases/latest` 天然排除草稿与 `--prerelease`，所以手动触发的 `build-<run>` 体验包不会推给用户 |
| 版本比较 | `domain/app-version.ts` 解析 `v0.1.7` 这类 tag，与 `app.config.js` 的 `version` 做 semver 比较（含预发布优先级）；**任一侧解析失败一律「不更新」**，避免误报 |
| 完整性 | 默认只取 GitHub API 的资产 `size`，APK 篡改由 Android 安装器校验签名；仅当 Release 说明显式提供 `SHA256: <64 位十六进制>` 时，App 才恢复全量哈希校验 |
| 镜像回退 | 顺序：说明里的 `APK-Mirror: https://...` → `https://gh-proxy.com/<github 资产地址>` → 直连；任一成功即止（`resolveDownloadUrls`） |
| 内存占用 | 仅在需要 SHA256 时才分块读取（当前 4MB 块，base64 → ArrayBuffer）后喂给增量 SHA-256，几十 MB 的 APK 不会一次性进内存 |
| 校验反馈 | 仅 Release 显式提供 SHA256 时，下载完成才进入 `verifying`：进度条保持满格，另给转圈 + 「正在校验安装包 x%」。默认策略直接进入可安装状态，避免几十 MB 全量哈希的等待；`verifying` 期间重复点检查 / 下载都会被状态机拦住 |
| 安装权限 | `app.config.js` 声明 `REQUEST_INSTALL_PACKAGES`；Android 8+ 首次需用户允许「安装未知应用」，卡片提供跳转 `android.settings.MANAGE_UNKNOWN_APP_SOURCES` 的入口 |
| 忽略版本 | 本地 key `update:ignoredVersion`（AsyncStorage），忽略后仍可点「仍要查看」强制检查 |
| 覆盖升级 | 依赖 `android.versionCode` 递增（CI 用 `github.run_number`），因此**必须始终用同一 keystore 签名**，否则系统拒绝安装 |

**新增一个下载镜像**：在 Release 说明里加一行 `APK-Mirror: https://你的镜像/xxx.apk` 即可，App 端无需发版（解析在 `domain/release-notes.ts`）。

### 19.11 原生开屏（冷启动第一屏）

**目的**：JS bundle 起来之前由系统绘制的那一屏，默认是白底无内容，冷启动会闪一下白。现在配成「应用图标居中 + 主题底色」：浅色用品牌绿，深色用 App 深色页面底，与启动器图标、应用内开屏（`components/SplashView`，底色取 `colors.bg`）视觉连贯。

`app.config.js` 里的三处约定：

- `ICON_PATH = './assets/icon.png'`：应用图标路径，`expo.icon`、浅色与深色开屏共用；
- `BRAND_COLOR = '#9DD9BE'`：唯一的品牌绿常量，`android.adaptiveIcon.backgroundColor` 与**浅色**开屏底色共用（改色只改这里）；
- `DARK_SPLASH_BACKGROUND = '#111111'`：**深色**开屏底色，等于 `src/theme/palette.ts` 的 `DARK_COLORS.bg`；
- `SPLASH_ICON_WIDTH = 200`：开屏图标展示宽度（约屏宽一半）；
- 插件：`['expo-splash-screen', { image, imageWidth, resizeMode: 'contain', backgroundColor, dark: { image, backgroundColor } }]`。

| 平台 | 表现 |
| --- | --- |
| Android 12+ | 系统 SplashScreen API 接管：`windowSplashScreenBackground` + `windowSplashScreenAnimatedIcon`（同一张 `icon.png`，由系统按当前主题遮罩成圆形 / 圆角方形） |
| Android 8~11 | 同一套主题资源，按 `resizeMode: 'contain'` + `imageWidth` 居中展示 |
| iOS | 生成 `SplashScreen.storyboard`：居中 200×200 图片 + 命名色 `SplashScreenBackground` |

校验与注意：

- `app.config.test.js` 守住「插件已配置 / 底色与自适应图标同色且合法 / image 是存在的 1024×1024 PNG / 依赖已声明」；依赖由 `npx expo install` 写入（`~0.29.x`），CI 的 `npx expo install --check` 会拦住 SDK 版本漂移。
- `npx expo config --type introspect` 会**真实执行配置插件**并打印最终原生配置，可用于确认产物：`colors.xml` 的 `splashscreen_background`、`styles.xml` 的 `Theme.App.SplashScreen`（`windowSplashScreen*`）、MainActivity 的 `android:theme`。
- 开屏是**原生资源**：改完必须重新构建（`release.yml` 打 tag 构建）才生效，重载 JS 无效。
- **深色模式**走 `dark` 变体：底色换成 App 深色页面底（`DARK_COLORS.bg`），**图标沿用同一张、不另做深色图标**；`app.config.test.js` 会比对原生配置与调色板的值，防止两处漂移。Android 落到 `values-night/colors.xml` 与 `drawable-night-*/splashscreen_logo.png`。
- ⚠️ `dark` 里**必须显式给 `image`**：插件的 Android 实现只在 `dark.image` 存在时才写夜间 drawable，省略它深色下就只剩纯色底、图标消失。
