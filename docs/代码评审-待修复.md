## 0. 本次新发现(启动链路 `e879821` / `8e84333` 之后)

### 0.1 🆕 启动快照的 `hydrate` 覆盖在途网络结果(中危,需复现)

`src/stores/transaction.store.ts:139-151`、`src/stores/category.store.ts:40-47`、`src/stores/tag.store.ts:57-64`

`hydrate` 通过整体 `set({ buckets })` / `set({ byLedger: snapshot })` 覆盖 store。`App.tsx` 中 `hydrate` 与 `load` 是串行的(先 hydrate 再 load),但**页面的 `useFocusEffect` 会在 `signedIn` 后立即触发 `loadMonth` / `loadCategories`,不等待 hydrate 完成**。理论上,若网络结果先于 AsyncStorage 读取返回,随后到达的旧快照会覆盖刚拿到的新数据,直到下一次 focus 才修正。

> ⚠️ 这是基于源码推断的时序风险,**尚未复现**。修复前应先写失败用例(模拟 `readSnapshot` 晚于 `loadMonth` resolve)确认。

**修复方向**:`hydrate` 只写入当前 store 中尚无数据的 key(合并而非覆盖);或在 `hydrate` 写入前检查对应 bucket 的 `status` 是否已为 `ready`。

### 0.2 🆕 账本列表加载失败对用户不可见(中危)

`src/stores/ledger.store.ts:117-143`、`App.tsx:46-58`

`ledger.store.load()` 失败时仅 `set({ status: 'error' })` 并抛错,`App.tsx` 用 `.catch(() => undefined)` 吞掉。全仓没有任何 UI 消费 `ledger.status === 'error'`(已 grep 确认)。冷启动在无快照且网络失败时,用户既看不到错误提示,也没有重试入口。

**修复方向**:在账单 / 首页接入 ledger 的 `error` 态,复用 `ErrorState` 并提供重试;`App.tsx` 的吞错改为至少记录状态。

### 0.3 🆕 「清除本地缓存」不会真正登出(低危,需复现)

`src/screens/settings/SettingsScreen.tsx:72-88`

该操作只调用 `AsyncStorage.clear()`,既不调用 `signOut`,也不清理内存中的 store。文案写的是「需要重新登录」,但:

1. 当前进程内的 `session` 仍然有效,界面不会跳转登录页(由源码可直接确认)。
2. ⚠️ 待验证:auth-js 续期后可能把内存 session 重新写回 AsyncStorage,导致登录态在下次启动时仍然存在,与文案不符。需在真机 / 测试中确认。
3. `AsyncStorage.clear()` 同时清掉了字号、深色模式、金额隐藏等**设备级设置**,与 `AGENTS.md` §2.5「登出时保留设备级设置」的原则不一致(该条原指登出,清缓存应同样保留)。

**修复方向**:清缓存应走 `signOut()` + 重置业务 store,并仅删除业务快照 key(`ledger:list:*`、`transactions:*`、`categories:*`、`tags:*` 等),保留设置类 key。
